# 実験計画 v0：要因の影響を測る探索段階

履歴：初期の探索計画。基盤は実装済みだが、以下には未実施の掃引・将来案を含む。2026年10月12日以降の目標と優先順位は[研究目標](../../overview/research-goals.md)、[段階計画](../../overview/roadmap.md)、[単独採食計画](../2026-10-12-single-agent-foraging/plan.md)を基準にする。「評価方法をまだ決めない」という以下の方針は開始時点の記録。

作成日：2026年10月11日

更新日：2026年10月11日。出生資源、個体別学習状態、変異尺度、交互作用の保持、L3の更新手順を修正した。学習の詳細は[学習更新仕様](../../protocols/learning-protocol-v0.md)を参照する。ここで固定する数値は探索用の開始値であり、適応や創発を保証する値ではない。

「高度さ」の評価方法や、試行錯誤のループは、まだ決めない。先に実験を走らせて、学習方式・パラメータ数・個体数・2D世界の設計などが、どの結果をどの程度変えるのかを測る。この段階の目的は仮説の検証ではない。**要因ごとの感度の地図**を作ることである。評価方法と試行錯誤のループは、その地図を見てから設計する（[§7](#7-この段階の後に決めること)）。

## 1. この段階で決めたこと

| 項目 | 決定 |
| --- | --- |
| 進め方 | 基盤と更新検査 → 世界の較正 → 一要因と少数交互作用のスクリーニング → 広い交互作用の探索、の4段階（§6） |
| 個体数 | 固定しない。初期個体数N0と最大個体数Nmaxを実験要因にする |
| 外的な課題報酬 | 使わない。§5の測定値は観測者専用で、個体の入力・報酬・勾配へ戻さない |
| 学習方式 | 一つに決めず、L0〜L3の4方式を要因として比べる（§3）。予測目的や内的スカラーを許容するかは、比較結果を見て判断する |
| v0の世界 | 食料、代謝、寿命、成熟、死亡、自己複製、二親繁殖、繁殖しない、通信路、体内感覚（要因） |
| v0に入れないもの | 睡眠、建築、狩り・攻撃、遮蔽、遺体の食料化。睡眠を導入する方針は維持し、v1で要因として追加する（§8） |
| 継承 | 出生時の遺伝情報のみを継ぐ（獲得した重みは継がない）。獲得重みの継承はv1の比較条件にする |
| 計算 | 個体ごとの重みを独立に保ったまま、個体と世界の軸でGPU上にまとめて計算する（§4） |
| 標本の単位 | 独立に初期化した世界（シード）。同じ世界の個体は独立標本に数えない |

## 2. 世界 v0

### 2.1 構成

- **地形：** 正方形のタイル世界。境界は壁。地図の一辺は `round(sqrt(100 × N0))` とし、初期密度を一定にする（N0=32なら57×57）。密度そのものは別の要因として変える。
- **固定障害物（2026年10月11日追加）：** 基準密度は内部タイルの4%。一辺1〜4タイルの塊や短い壁を散らし、全ての通行可能タイルの連結を保つ。初期配置・移動・出生・食料生成で同じ通行判定を使い、局所RGBには外壁と同じ灰色を使う。配置は世界別の専用乱数で固定し、保存・再開・観察リプレイに含める。密度0を障害物なしの比較条件として残す。視覚・音は上記のv0仕様を用いる。以前の障害物なしの較正・速度表と区別し、資源供給量は必要に応じて再較正する。
- **食料：** 1種類。シードごとに固定した肥沃度マップ（数個のパッチ）を置き、空きタイルに確率 `g × 肥沃度` で食料が生える。1個でエネルギー10。採り尽くしても回復する。
- **個体の身体：** 位置、向き（4方向）、エネルギー（上限100）、年齢。管理側が試行開始時に作る創始個体は`E_founder=50`、繁殖・自己複製で生まれる子は`E_child=30`とする。エネルギーが0になるか、年齢が寿命Lに達すると死亡する。
- **寿命と成熟：** 基準寿命`L=3,000 tick`、成熟年齢`M=max(1, round(0.1L))`。基準では300 tickで成熟する。Lを変える条件ではこの比率を保ち、「寿命と成熟周期」の組として解釈する。
- **代謝：** 開始値は基礎代謝`0.02/tick`、移動成功時の追加費用`0.01`。Phase 1で基礎代謝とgを較正し、決めた値は同一試行中に変更しない。初期のgは`1e-4`を掃引の起点にする。脳の大きさに応じた代謝費は、v0では課さない（v1の要因）。

### 2.2 行動

行動は4つの成分に分け、同じtickに組み合わせて出せる。

| 成分 | 選択肢 |
| --- | --- |
| 移動 | 静止、前進、左回転、右回転 |
| 口 | 何もしない、正面のタイルを食べる |
| 発信 | 沈黙、記号1〜K |
| 繁殖 | しない、自己複製、交配を受け入れる |

食べる動作は自動化しない。「最寄りの食料へ移動する」のような技能も用意しない。

### 2.3 繁殖

- **自己複製：** 本人が自己複製を選び、成熟していてエネルギーが`E_child+B`以上、出生位置と容量枠が確保できれば成立する。親は40を支払い、子は30を受け取る。出生は即時で、妊娠期間は設けない。
- **二親繁殖：** 隣接する2個体が、同じtickに両方とも「交配を受け入れる」を出し、両方とも成熟していて費用を支払える場合に候補となる。各親が`(E_child+B)/2=20`を支払い、子は30を受け取る。候補が重なった場合の組み合わせは、シード付きの抽選で決める。一親が同じtickに複数出生へ使われないようにする。
- **初期値：** `E_child=30`、`B=10`。自己複製と二親繁殖で追加負担Bは同じにする。
- **上限：** 個体数がNmaxに達しているときは、費用を引く前に出生を不成立にする。Nmaxの初期値は `4 × N0`。既存の個体を間引くことはしない。

親の生存・費用、隣接する空き位置、容量をすべて判定し、同時出生の競合を解いてから、費用の引落しと子の登録を一つの処理として確定する。不成立なら費用を引かない。出生による親子のエネルギー総量の差は両方式とも`-B=-10`である。創始個体の50を子へ流用しない。死亡枠への出生は新しい個体IDを使い、旧個体の最終遷移と学習状態を子へ混ぜない。

### 2.4 観測

- **視覚：** 身体の向きを上にした局所視野で、半径rタイル。各タイルを固定の色1画素で描く。サイズは `(2r+1)×(2r+1)×3` で、r=5なら11×11×3になる。物体は色で区別できるが、種類のラベルは渡さない。系統を示す色も使わない。調査報告間で食い違っていた32×32と48×48の解像度は、v0ではこの方式に決める。1タイルを複数画素で描く高解像度版は、後で要因として加える。
- **音：** K記号それぞれの受信強度を並べたベクトル。基準`R_s=10`タイルとし、マンハッタン距離dがR_s以下の他者の発信を`1/(1+d)`で減衰させ、記号ごとに足して強度1でclipする。発信者のIDや方向は渡さない。遅延は1tickで、自分の音は聞こえない。v0の明示的な発信費用は0だが基礎代謝は続く。音の費用や形式の変更は別設定にする。
- **体内感覚：** 自分のエネルギー量。既定は「あり」で、「なし」を除去比較にする。
- **遠心性コピー：** 直前に自分が出した行動。
- **方位センサー（任意の比較条件）：** `absolute` は北・東・南・西の4次元one-hotを常時与える。`masked` は同じ4入力をゼロ固定し、`none` は入力枠なしの従来条件。相対的な前進・左右旋回と半径5の視界は維持する。方位は報酬や追加の予測対象には入れない。[実装・比較仕様](../../protocols/compass-input-design.md)。
- **渡さないもの：** 座標、全体地図、他個体の内部状態、個体数、Nmaxの空き状況。

### 2.5 更新順序

[環境設計の調査§4](../../research/environment-design.md#4-時間更新順序描画の分離)の案をそのまま採用する。全個体の行動を同時に集めてから、競合を抽選で解決し、世界を更新する。個体の時間は実験内のtickで数え、計算の遅さで年齢や機会が変わらないようにする。

## 3. 学習方式（要因）

4つの方式は、身体・観測・行動の仕様を共通にし、学習の仕組みだけを変える。v0はMLPエンコーダ→GRU→共通の特徴層→成分別行動ヘッドとする。層構造、更新対象、1遷移の処理順は[学習更新仕様](../../protocols/learning-protocol-v0.md)に定める。幅hは要因であり、固定パラメータ数の上限ではない。

| 方式 | 生涯の中で変わるもの | 世代で変わるもの | 何を測るためか |
| --- | --- | --- | --- |
| **L0 進化のみ** | 再帰状態と全方式共通の観測正規化統計（重みは固定） | 初期重み（突然変異） | 生涯の重み更新なしの基準（JaxLifeやHamon et al.を参照） |
| **L1 局所可塑性** | 一部の層の重みを、報酬も誤差も使わないHebbian/Oja則で更新する | 初期重みと、層ごとの可塑性係数 | 目的を最も少なくした生涯学習 |
| **L2 予測学習** | 次の観測を予測する損失で、エンコーダと再帰コアを更新する。行動ヘッドは固定 | 初期重みと学習率 | 予測の学習だけで行動が変わるか（Nolfi et al. 1994と同型） |
| **L3 予測＋内的評価** | L2に加えて、遺伝評価器の出力とStream-AC由来の適格度トレース・更新制御で行動・価値ヘッドを学習する | 初期重み、評価器の係数、学習率 | 内的評価で行動を学ぶ場合 |

- **L3の評価器：** `r = tanh(w · φ)`。φは固定の基底で、エネルギーの変化（体内感覚がある場合）、視野の平均色の変化、受信した音の強さ、行動を並べたものである。係数wは遺伝し、符号は固定しない。創始個体のwは小さな乱数にする。v0では評価器は生涯の中で変化しない。生涯の中で評価器が変化する仕組みは、v1の要因にする。
- **L3の学習の安定化：** [Elsayedらのv3](https://arxiv.org/html/2410.14606v3)を参照し、個体別正規化、LayerNorm、適格度トレース、要素別の更新上限を定義する。感覚予測部分は個体別Adam、行動・価値ヘッドはStreamingOptimizer由来の規則に分ける。GRUとヘッドのみのRL、密な初期化は原論文との差分であり、完全なStream-X再現とは呼ばない。
- **二親の継承：** ネットワークの重み一式は、どちらか一方の親から等確率で受け継ぐ。学習率・可塑性係数・評価器係数などの小さな遺伝子は、両親から交叉する（[アーキテクチャ報告§8](../../research/architecture-learning.md#8-二親の継承と自己複製)）。
- **突然変異：** 下記の種類別規則を使う。単位の異なる全遺伝子へ同じ絶対σを加えない。
- **パラメータ数：** 再帰コアの幅hで変える。学習ヘッドを含む実数を実装後に数え、感覚・再帰・行動・予測・評価ごとに記録する。視野やKでも入力・出力次元が変わるため、hだけを総パラメータ数の代理にしない。

### 3.1 遺伝情報と突然変異

親の出生時遺伝情報と、生涯中の重み・状態を別に保存する。二親で小遺伝子を交叉し、ネット一式の提供親を選んだ後、子の遺伝情報へ一度だけ変異を加える。自己複製でも同じ変異規則を使う。学習で変わった親の重みに雑音を足して継承する方式にはしない。

| 遺伝子の種類 | 変異規則 | 範囲と比較尺度 |
| --- | --- | --- |
| 通常の重みW_l | `ΔW_l=mu*s_l*epsilon`、epsilonは要素ごとの標準正規乱数 | `s_l=1/sqrt(fan_in_l)`を固定参照尺度にする。層ごとの`RMS(ΔW_l)/s_l`を記録 |
| bias | 同じ層の固定s_lを使う | 元のbiasが0でも変異尺度が0にならない |
| LayerNormのscale・offset | 参照尺度1で符号付き雑音を加える | 数値安定化の範囲[-5,5]へclipし、飽和率を記録 |
| 正の学習率・可塑性率 | `q=log(rate)`へ標準偏差muの雑音を加え、許可したlog範囲へclipしてexpで戻す | 基準値と範囲は学習更新仕様の表。負の学習率を生成しない |
| 遺伝評価係数w | 参照尺度0.1で符号付き雑音を加える | [-2,2]へclip。符号は固定しない |

muの開始水準は小0.01・中0.05・大0.10とする。muは絶対重みの標準偏差ではなく、上表の参照尺度に対する倍率である。各層の正規化RMS変化を比較し、モデル規模が違えば機能の変化まで同じとは仮定しない。出生前後で同じ検査入力への行動分布の差も観測者用に記録する。

変異対象は浮動小数の遺伝変数だけで、個体ID、年齢、乱数カウンタ、optimizer状態、出生時にリセットするhiddenは対象にしない。NaN・Infが出た場合を生物の死亡として処理せず、数値異常として試行を止めて記録する。

## 4. 計算の方針

- 個体の重みは`[世界, 個体枠, ...]`の形に積む。枠番号と個体IDは分け、生存していない枠は重みと全学習状態の更新を止める。
- L2・L3の予測損失は個体ごとの**総和**を微分する。Adamのm・vだけでなく、bias correctionに使う実更新回数tも`[世界, 個体枠, optimizer群]`で持つ。通常のAdamを積んだParameterへそのまま適用せず、個体別tの関数型更新を使う。L3のRL更新は別の個体専用トレースと更新制御状態を使う。
- 出生時は、勾配、hidden、局所可塑状態、前行動、Adamのm・v・t、RLトレース、更新制御の蓄積、観測・報酬統計をすべて初期化する。死亡枠の最終更新を完了してから子へ再利用する。詳細と独立実装との照合条件は[学習更新仕様](../../protocols/learning-protocol-v0.md)に定める。
- 個体の独立性を壊さないよう、次の点を守る。
  - 勾配クリッピングや正規化を、全体のノルムでかけない。個体ごとにかける。
  - バッチ正規化のように個体間で統計を共有する層は使わない。
- 世界の更新も同じGPU上でテンソル演算として書く。複数の世界を一つのバッチにまとめて同時に走らせる。
- GPUは3枚とも独立した実行先として使う。世界を割り振るだけで、GPU間の通信は行わない。
- パラメータ、勾配、optimizer、トレース、再帰状態、観測、一遷移のグラフ、出生時コピーを含むピークが収まらない組合せは実行せず、除外したことを記録する。世界バッチ数も見積りに含める。P×Nmaxの重みだけで可否を決めない。

## 5. 測る量（評価ではなく記述）

ここで測る量は「高度さ」の評価ではない。要因がどこに効くかを見るための、幅広い記述統計である。すべて観測者専用で、個体へは戻さない。

| 分類 | 測定量 |
| --- | --- |
| 存続 | 全滅したか、全滅までの時間、個体数の推移（平均と変動）、Nmaxに達していた時間の割合、出生が拒否された数 |
| 生態 | 個体1tick当たりの摂取量、食料の現存量、死因（餓死か寿命か）、方式別の出生数、到達した世代の深さ |
| 生涯の変化 | 年齢に対する摂取率の傾き（L0と比べる）、重みの変化量 |
| 世代の変化 | 創始個体からの遺伝子の距離、遺伝的多様性、子孫が残っている創始系統の数 |
| 行動 | 行動成分ごとのエントロピー、移動範囲、繁殖方式の選択頻度、発信の頻度とエントロピー |
| 固定プローブ | 一定間隔で個体の凍結コピーを抜き出し、共通の検査用地図に1体ずつ置いて試す。最初の採食までの時間と、一定時間内の摂取量を測る。ランダム方策と、台本どおりに採食する方策の値も並べて、尺度の目安にする。プローブの結果は世界へ戻さない |
| 計算 | 個体ステップ/秒、壁時計時間、メモリのピーク |

集計値は1,000tickごとに記録する。出生と死亡は、イベントごとに系統ログとして残す（親ID、方式、tick、死因）。

## 6. 段階

### Phase 0：基盤

1. 世界v0、個体の並列計算、L0〜L3、[学習更新仕様](../../protocols/learning-protocol-v0.md)、ログ、チェックポイントを実装する。プロジェクトはまだgit管理されていないので、最初にgit管理を始める。
2. 世界を検証するための方策を2つ用意する。ランダム方策と、台本どおりに採食する方策である。どちらも世界の検証にだけ使い、個体の教師にはしない。
3. 出生でエネルギー総量がBだけ減り、不成立なら変わらないことを確認する。出生・死亡・枠の再利用を含めて、個体別Adamとトレースの独立性、更新対象、正の学習率、detach範囲を検査する。学習更新仕様の確認条件を通す。
4. 保存から再開したとき、同じ行動列で世界の状態ハッシュが一致し、学習状態と乱数も復元されることを確認する。
5. まず小さい診断設定で4方式の有限な出力と更新を確認する。その後、基準N0=32・h=64で各3独立シード、最大9,000 tickの短いパイロットを行う。正常な全滅は結果として残し、NaNや状態漏れのある試行は正常な全滅と混ぜない。複製の成立しない設定では、出生処理の検査を別の検証用方策で行う。
6. 速度を測る。個体枠数 {32, 128, 512, 2048} × 幅h {16, 64, 256, 1024} × 方式 {L0, L3} を、GPUの種類ごとに測る。この表を以降の実験予算の基準にする。空き枠だけの高速さを測らず、実活動数・学習数と出生時ピークを併記する。

### Phase 1：世界の較正

1. 2つの検証用方策で、食料の再生率gと基礎代謝を掃引する。「ランダム方策の集団は寿命の2〜3倍の時間で全滅する」「台本どおり採食する方策の集団はNmax未満で存続する」の両方を満たす範囲を探し、その中央を基準の世界にする。目的は、学ぶ価値はあるが、学ばなくても生き残れるわけではない世界を選ぶことである。
2. 検証用の採食方策にも成熟後の自己複製を明示し、採食だけして寿命で消える集団を「存続する方策」として使わない。ランダム方策の繁殖成分も設定に記録する。これらの方策は主個体へ移植しない。
3. 基準の世界でL0を走らせる。N0 ∈ {8, 32, 128, 512} それぞれ5シード。すべて全滅するようなら、初期に資源が豊富な期間を設けるなどの手当てをし、そのことを記録する。環境を変更したらL0〜L3の短いパイロットも再実行する。

4. ランダム方策の条件選択では、各世界に少なくとも1回の採食経験があることを必須にする。平均採食回数だけで合格にせず、採食0回の世界数と全シードの値を残す。現在の探索は2,000tick存続・10,000tickまでの全滅も合わせて判定する。選択には複数シードを使い、未使用シードで確認する。確認失敗を見て調整した集合は調整用に変更し、別の未使用集合で再確認する。この較正基準を個体の外的報酬へ転用しない。長方形の縦横比は固定せず探索対象にする。[現在の結果](../2026-10-11-random-feeding-calibration/results.md)。

### Phase 2：一要因と少数交互作用のスクリーニング

基準の条件から一つの要因だけを変える。方式はL0とL3の両方で行い、各条件5シード、10万tickを上限とする。

| 要因 | 基準 | 他の水準 |
| --- | --- | --- |
| 学習方式 | L0, L3 | L1, L2 |
| 幅h（パラメータ数） | 64 | 16, 256, 1024 |
| 初期個体数N0（密度は一定） | 32 | 8, 128, 512 |
| 密度（N0は固定、地図の面積を変える） | ×1 | ×0.5, ×2 |
| 食料の再生率g | 較正値 | ×0.5, ×2 |
| 食料の分布 | パッチ | 一様 |
| 視野の半径r | 5 | 2, 8 |
| 体内感覚 | あり | なし |
| 通信の記号数K | 4 | 0（通信なし）, 16 |
| 繁殖方式 | 両方選べる | 自己複製のみ, 二親のみ |
| 寿命L（成熟期間も比例させる） | 3,000 | 1,000, 10,000 |
| 正規化した変異強度mu | 中0.05 | 小0.01, 大0.10 |
| 試行の長さ | 10万tick | 基準条件だけ100万tick以上を数本 |

一要因部分は従来の約240試行を計画量の目安とするが、実際の数は設定一覧を生成し重複を除いて数える。L1・L2、下記の交互作用、長時間試行を別に予算へ加える。各試行の費用はPhase 0の速度表から事前に見積もり、一括投入前に方式ごとの短いパイロットを通す。

単独で効かなかった要因も組合せで効く可能性があるため、次の少数要因計画をPhase 2から必ず残す。各セルは他の条件を基準にし、同じ5つの独立世界シードを使う。シードを対応させても、分岐後の軌跡が同じとは仮定しない。

| 保持する組合せ | 水準 | 対象方式 |
| --- | --- | --- |
| 通信×繁殖方式 | K={0,4} × {自己複製のみ, 二親のみ, 両方} | L0とL3 |
| 学習方式×寿命 | {L0,L1,L2,L3} × L={1,000,10,000}、成熟比0.1 | 全方式 |
| 変異×モデル幅 | mu={0.01,0.10} × h={16,1024} | L0とL3 |

全セルを数えると5シード込みで140試行だが、一要因部分と重なる設定は再実行せず同じ結果を参照する。設定生成後の実数と計算時間を記録する。資源不足で実行できないセルは失敗結果ではなく未実行として残す。

### Phase 3：交互作用の探索

1. Phase 2で主効果または交互作用が見られた要因と、上表の組合せを構成する要因を残す。単独差が小さいことだけで後者を除かない。初期の探索予算の20%は、絞り込み前の実行可能な全要因範囲を覆う設定へ確保する。
2. 連続値にはLatin hypercube等を使い、学習方式・繁殖方式・資源分布などのカテゴリは層別に割り当てる。100〜200設定、各2〜3独立シードを予算の目安とし、設定一覧を作ってから費用を確認する。
3. §5の測定量ごとに重要度と交互作用を調べる。モデルの学習用と確認用の世界シードを分け、置換重要度だけで因果関係を確定しない。探索で見つけた組合せは別シードで確認する。

### 8.1 v1の小規模統合へ進む条件

Phase 0の資源収支・独立更新・保存再開が通り、Phase 1で採食可能な較正世界を得て、L0〜L3の短いパイロットと速度表がそろった時点で、小規模な睡眠・記憶統合の計画を作る。Phase 2・3をすべて終えることを前提にしない。

最初は実経験再処理、速い記憶と遅い記憶、その組合せを、処理なし・同量の覚醒時処理と比べる。Dreamingは保持した実経験で予測器と仮更新を検査できてから追加する。v0で存続しなかったことだけでこれらの機構を却下しない。

Phase 2・3の一括実行前に総GPU時間の上限を決め、その10%をv1小規模統合の実装確認・速度測定・対照試行へ予約する。残り90%以内でv0の設定数・シード数を調整し、v1の方式別試行数は実測後に固定する。この予約は移行のための初期配分で、最適な比率を主張しない。v1の比較で環境や更新則を変えた場合、v0の感度の地図をそのまま外挿しない。

## 9. 解析と記録の約束

- 結果は、世界シードを単位とする分布で報告する。全滅した試行も除外しない。
- スクリーニングでは条件差、世界シード間のばらつき、標準化した差とその不確かさを併記する。差が標準偏差を超えることは探索用の目印にとどめ、単独で超えなかった要因を交互作用の候補から自動除外しない。5シードの結果を確定的な効果判定と扱わない。
- 設定はファイルに書き、そのハッシュを試行IDにする。設定、コードのバージョン、乱数シード、測定結果を一つの表に追記していく。
- 乱数の流れは用途ごとに分ける（世界、個体の初期化、行動のサンプリング、出生と突然変異）。個体が1体増えただけで、世界側の乱数がずれないようにする。
