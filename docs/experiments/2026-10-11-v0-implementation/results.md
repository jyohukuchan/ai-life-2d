# v0実装・実行の検証記録

実施日：2026年10月11日。目的は世界・独立学習・記録・観察が動くことと、手元で短い試行を回せる速度を確認することである。学習の優位性、知能や言語の成立を実証する実験ではない。

機械可読な測定値は [validation-results-2026-10-11.json](data/validation-results-2026-10-11.json)、操作手順は [running-v0.md](../../operations/running-v0.md)。生の試行ファイルはプロジェクト内の `runs/` に残している。

## 環境

- CPU：AMD Ryzen Threadripper PRO 3995WX、64コア・128論理CPU。試行プロセスのPyTorchスレッドは4。
- メモリ：約110 GiB。GPU：Radeon Pro V620 ×2、Radeon AI PRO R9700 ×1、各約32 GB。
- Python 3.12.3、PyTorch 2.12.0+rocm7.14.0、HIP 7.14.60850。AMD multi-arch wheelでgfx1030・gfx1201を導入。依存は `requirements-rocm.lock` に固定。
- 最初の複数GPUを同一プロセスで順に使う検査ではsegfaultが発生した。原因は未確定。その後は `ROCR_VISIBLE_DEVICES` でGPUを分離し、V620とR9700それぞれで行列演算・逆伝播・実際のシミュレーションを完了した。この実装では一プロセス一GPUを使う。

## 機能検査

` .venv/bin/python -m pytest -q `：**22件成功**。Starlette/httpxの非推奨通知1件あり。

- 複製・二親繁殖のエネルギー収支、容量上限時の非課金、出産でエネルギーを使い切った親の死亡、衝突排除、通信の遅延・自己音除外。
- L0〜L3の更新対象、非活動個体の凍結、独立Adamとの一致、出生時の遺伝基底の継承とoptimizerのリセット。
- 死亡枠を同tickで子が再利用したときの旧個体の最終観測と、子の状態リセット。
- RLヘッドの要素別更新上限・終端bootstrap、合成遷移での予測損失低下。合成検査の重みや経験は主試行へ使わない。
- メモリ内およびディスクcheckpointからの再開で、世界・重み・全学習状態が中断なしの実行と一致。SIGTERMでも一遷移を完了して保存。
- 観察あり・なしでCPUの世界と重みが一致。観察APIは読み取り専用。全滅した区間も予定通り保存。
- GPUでも別途、保存・復元後の世界と全ネットワーク重みの一致を確認。

Chromiumで実画面を開き、描画・リプレイ再生・スクラブ・個体追跡・モバイル表示・JavaScriptエラーなしを確認。最終検査ではリプレイを停止している間に世界がtick 721から791へ進んだ。証跡：`runs/validation-final/browser-check.json` と同ディレクトリのスクリーンショット。

各方式3世界。世界シード42・1051・2060、初期32・容量128・幅64・一個体65,497パラメータ。毎遷移の更新、ライブ抜き取り表示、事前にランダム選択した3区間、統計・出生死亡記録・定期および最終checkpointを含む。計108,000世界tickを実行。

全方式で採食、複製、二親繁殖、エネルギー死・寿命死が発生し、12世界は9,000tick時点でも個体が生存していた。L0でも世代が続いており、出生や存続だけを学習の効果とは扱えない。各方式3シードだけであり、CPUとGPUも混在している。この表は機能確認で、方式の因果的な性能比較には使わない。

L3の長いパイロットは約204秒、PyTorchの最大割当て量約0.84 GB。ドライバやライブラリの全VRAM使用量とは異なる。最新の追加状態検査を含む別の1,800tick実行も完了した。

## 観察と保存の状態

- 観察サービス：`ai-life-2d-viewer.service`。同じLANから `http://192.168.0.66:8765` のhealthとゲーム画面へ到達できる。
- ランダム選択は実行前に保存。世界×開始tickから一様に選び、別の観察用乱数を使用。固定長・連続tickで保存し、失敗・全滅を除外しない。イベントで選んだ動画への選別は行っていない。
- ブラウザの停止・再生速度・接続は世界の進行を操作しない。リプレイは学習用の経験再生には使わない。
- インターネット向けの常設URLや公開トンネルは起動していない。外部閲覧には実行手順のSSH転送を利用できる。

## 除外・限界

最初のL0・L1のCPU試行は、コードハッシュを出力する機能の追加前に開始した。L2・L3以降は `metadata.json` にコードハッシュを記録している。

CPUで誤って起動したL2は中止し、`runs/pilot-L2/summary.json` に中止理由を残した。自然な全滅や完走試行には数えず、GPUで新規実行したL2へ置き換えた。ブラウザの進行検査を完了済みの世界へ向けた一度の実行は「世界が進まない」として検査に失敗したため、実行中の新規試行で取り直し、上記の進行を確認した。

この段階で確認したのはv0の動作と資源負荷である。正式な資源較正、全ベンチマーク格子、長期の学習効果・協調・通信の意味の検証、Phase 2・3の条件比較、睡眠・記憶のv1統合は未実施。現在の小さなモデルで「知能が生まれた」とは判断しない。
