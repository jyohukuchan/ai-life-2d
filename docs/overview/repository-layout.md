# リポジトリ構成と記録規約

更新日：2026年10月12日。長期方針、実験ごとの証拠、実行成果物を別々に管理する。

```text
README.md                       現在地と主要文書への入口
docs/
  README.md                     文書案内
  overview/                     目標、段階計画、判断履歴、構成規約
  experiments/<実験ID>/         特定実験の計画・結果
    plan.md                     開始前の問い、条件、分析、停止条件
    results.md                  結果、解釈、限界、再計算方法
    data/                       レポートに対応する小さい集計データ
    figures/                    レポートに対応する図
  protocols/                    実装済みの学習・感覚等の仕様
  operations/                   実行、保存、再開、観察
  research/                     先行研究、レビュー、未採用候補
  templates/                    新しい計画・結果のひな形
  archive/                      廃止・改訂前の全体構想
configs/
  baselines/                    実装済みの共通動作確認設定
  experiments/<実験ID>/         個別実験の実行用YAML
scripts/                        実行・解析・検証・計測の安定した入口
src/ailife/                     実験環境と学習の共通実装
tests/                          共通実装と実験処理の検証
runs/                           生データ、checkpoint、保存済みコード
```

## 実験の単位

新しい実験IDは `YYYY-MM-DD-short-topic` とし、文書と設定で共有する。同じ実験の条件・反復・セッション・解析は実験IDにひもづける。2026年10月12日以前の実行ID（`rep20-20261012`等）は変更せず、[実験一覧](../experiments/README.md)で対応づける。

個別の計画・結果を `docs/` 直下やプロジェクトREADMEへ追記し続けない。READMEは現在地、一覧は状態と入口、本文は実験ディレクトリに置く。全体目標を変更したら `overview/` と判断履歴を更新する。

開始前の計画は実行時の版を保存する。開始後に重要な条件を変える場合は変更日・理由・適用試行を追記し、保存済みの計画を上書きして事前計画のように扱わない。新旧の条件を混ぜて集計しない。

## 実装・候補・履歴

`protocols/` は実装と対応する仕様を置く。未実装の改善案は個別計画や先行研究に置き、実装と検証の後で仕様へ反映する。計画の状態は「提案／較正中／実装中／実行中／完了／停止」等を明示する。

過去の実験結果は、現在も研究上の証拠なので `experiments/` に保持する。`archive/` へは改訂前の全体構想を置く。研究報告の推奨と採用済み機構を区別し、[未採用候補](../research/not-adopted.md)も残す。

## 設定とスクリプト

設定は単体で読み込める完全なYAMLを基本とする。派生関係は計画に記録し、現在ない設定継承機能を前提にしない。数値較正前・機能未実装の案を実行可能な設定として置かない。

スクリプトは既存のファイル名と呼び出し位置を保つ。保存済みコードや実行手順との互換性を保ち、用途は [scriptsの案内](../../scripts/README.md)で分類する。新しい処理が共通化されたら `src/ailife/` に移し、入口スクリプトは薄く保つ。スクリプトをさらに階層化する際は、相互呼び出しと保存コードの実行を別変更として検証する。

## 生データと再現性

既存の `runs/` は移動・削除しない。観察サーバーと実行処理は現在 `runs/<試行ID>/` と直下のstudy JSONを読むので、新しい試行もこの配置を使う。階層化するなら、サーバー、再開、解析、manifestのパス解決を先に対応させる。

生ログ、初期・最終checkpoint、選抜モデル、保存済みコード、実行計画、検証記録は `runs/` に保存する。小さい集計データと図だけを `docs/experiments/<実験ID>/data/`・`figures/` に置き、元データと再計算方法を結果に記す。文書へコピーした数値を新しい独立実験として数えない。

`runs/` はGit管理対象外。長期保存では、再実行に必要な設定・コード・初期状態と、重い途中checkpointの保存方針を実験開始前に決める。今回の整理では保存期限の設定や削除を行っていない。

## 今回の移動

旧 `docs/*.md`・`docs/*.json`・`docs/assets/` と `configs/*.yaml` を役割・実験ごとに移した。旧README本文は改訂前の構想として保存。Markdownリンクと現行スクリプトの設定パスを更新した。

旧パス→新パスと、内容を変えずに移したJSON・YAML・画像のSHA-256は[移動記録](path-migrations-2026-10-12.json)を参照。過去の生データ内にある旧パスは、その実行当時の記録として保持する。保存済みコードやmanifestのハッシュを変えない。
