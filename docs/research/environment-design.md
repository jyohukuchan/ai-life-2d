# 専用2D人工生命環境の設計調査

調査日: 2026-10-11。対象: [README](../archive/concept-before-curriculum-2026-10-12.md) の構想。事前学習なし、独立した生涯学習、外的な課題報酬なしを維持する。ここにある環境仕様・数値は**未採用の提案**であり、学習や創発を保証する値ではない。実装、依存導入、GPU性能測定は今回行っていない。初期個体数は調査時点で8個体としていたが、2026-10-11に固定条件から外し、実験要因として比較することにした（[実験計画 v0](../experiments/2026-10-11-v0-implementation/plan-v0.md)）。本文に残る8個体・8体の数値は、当時の前提による例示である。

## 1. 結論と優先順位

最初に作るべきものは、局所感覚で操作する小さな2D世界と、その因果関係を検証できる実験基盤である。写実的な物理、複雑なクラフト、大規模な個体群より先に、観測契約、更新順序、資源収支、死亡・出生、容量制約、保存・再開を明文化する。

環境の物理的な生存条件と、学習器に渡す報酬は別である。空腹で死ぬ世界を作っても、ランダム初期化されたネットワークが採食を学ぶとは限らない。死亡・繁殖による系統選択は、個体の生涯内に有用な勾配や評価信号を自動生成しない。環境側ができるのは、学習可能な因果構造と観測機会を用意し、成立しなかった理由を切り分けることである。

| 優先度 | 要素 | 最小実装で必要な理由 | 最初は省ける部分 |
| --- | --- | --- | --- |
| P0 | 局所観測・身体操作・入力契約 | 全体状態や意味ラベルの漏れで実験の問いが変わる | 写実画像、3D、複雑な運動力学 |
| P0 | 固定した実験内時間・同時行動・公平な競合解決 | ID順、GPU速度、描画速度が勝敗や寿命を決めるのを避ける | 非同期の現実時間サーバー |
| P0 | エネルギー・食料・寿命・死亡 | 生存と資源利用の因果関係、有限の生涯を定義する | 多種類の栄養、疾病、複雑な加齢 |
| P0 | 二親繁殖・自己複製・不実行、出生上限、系統記録 | ユーザーの中心的な問い。成立条件と選択を区別する | 性別、妊娠器官、複雑な育児 |
| P0 | 意味未定義の通信路 | 当初から利用可能にし、後付けした学習条件と区別する | 文法、単語、相手ID指定、言語教師 |
| P0 | 保存・再開・乱数分離・観測と評価の分離 | 失敗の再現、介入比較、外的報酬の混入防止 | 常時動画、すべてのテンソルの全保存 |
| P1 | 資源再生・枯渇・地形偏り・運搬 | 探索、接触、競争、生態的な分化を可能にする | 季節、多層流体、巨大マップ |
| P1 | 睡眠状態と計算予算 | 世界内の休止と内部学習の効果を区別する | 最初からの複雑な疲労生理 |
| P1 | 狩り・機能を持つ建築 | 必須の最終研究要素だが、採食・操作の成立後に追加可能 | 学習する獲物、多段クラフト、所有権制度 |
| P2 | 複数の生態、災害、季節、環境継承の比較 | 既存条件への適合と、適応・頑健性を区別する | 最初の統合実験では保留 |

P1は最終構想からの削除を意味しない。P0の動作確認だけで「協調や知能が出なかった」と結論づけない。

## 2. 最初に作る具体的な環境案

### 2.1 小さな局所世界

以下を最初の探索用設定とする案を推奨する。正当化された最適値ではない。

| 項目 | 仮設定・探索範囲 | 注意 |
| --- | --- | --- |
| 地形 | 48×48タイル、有限境界、4方向の身体向き。比較で32×32 / 64×64 | 地図の面積と密度を同時に変えた効果を分離する |
| 初期個体 | 調査時点の案は8体（現在は要因として比較）。地形・食料に対して到達可能な出生地点をシードで選ぶ | 常に同じ方角に食料を置くと、方角固定の習性が成立する |
| 個体上限 | 計測前のデバッグ候補16、統合候補32。16 / 32 / 64を容量感度の候補にする | GPU学習性能が未確認のため、32体が動くとは断定しない |
| 局所視覚 | 身体中心・身体向き基準、距離7タイル程度、前方視野、遮蔽あり、32×32程度のRGB | 感覚形式を専用2D用に再設計する提案。後述の契約を先に確定する |
| 通信 | 沈黙＋4種類程度の音。単一の局所共有音場、到達距離10タイル程度、1 tick遅延 | 記号に意味を付けない。音源IDや相手位置は別入力しない |
| 行動 | 前進・後退・左右回転・静止、正面への把持/放下/摂取/打撃/設置/撤去、送信、繁殖状態、睡眠 | 目標座標への移動や「最寄り食料へ行く」等の技能は与えない |
| 採集 | 1種類の可搬・可食物。2〜4の資源パッチ、局所再生、運搬上限1〜数個 | 最初の食料種類を増やす必要はない |
| 身体 | 有限のエネルギー、損傷、基礎代謝。年齢上限と成熟期間 | 体内状態の感覚への露出は別途明示する |
| 繁殖 | 隣接した二者の同時受容、または単独の複製開始。成熟・資源・所要時間を満たす必要 | 接近だけで自動出生しない |
| 世界運用 | 連続世界。出生・死亡は世界内で進み、保存点でリセットしない | 全滅ならその試行を終了 |

境界をトーラスにすると端の有利不利は減る一方、見えない接続が新しい学習課題になる。最初は境界の壁を局所的に見せる有限世界にし、境界付近の占有・死亡を記録する。比較ではトーラスも使えるが、同一条件とは扱わない。

### 2.2 数値は絶対値より比率を先に調整する

実装の動作確認には、エネルギー上限100、初期値60、基礎代謝0.02/tick、移動追加コスト0.01、食料1個10、最大年齢8192 tick、成熟512 tick、繁殖所要64 tick程度を仮置きできる。**これらは学習に十分な生涯の長さを示すものではない。** 選定する事前学習なしのモデルが更新できる回数・経験量を見て、主実験の寿命を決め直す必要がある。

先に掃引すべき比率は、無採食で生きられる時間/成熟時間、寿命/成熟時間、食料到達時間/無採食生存時間、再生流量/(初期集団の基礎代謝)、出生費/エネルギー容量、成熟時間/繁殖間隔、視野距離/資源間距離、通信距離/視野距離である。資源流量の比較候補は初期集団の基礎代謝の0.8 / 1.5 / 3倍程度とし、移動・損傷・繁殖・食べ残しまで含む実収支を測る。比率だけで環境の持続可能性は保証されない。

最小版を定数方策・ランダム方策・検証用の単純な採食方策でも走らせる。これは物理と到達可能性の検証であり、主実験の個体への教師や事前学習には使わない。完全に不活動な個体の死亡時刻、食料の最大供給、操作失敗率、出生費の保存を確認する。

## 3. 局所観測と身体的操作

### 3.1 観測契約

観測を変更するたびに、`observation_version`、視野、解像度、遮蔽、遅延、センサー雑音を実験条件に記録する。以下を主実験の暗黙の入力にしない。

- 全体地図、真のx/y、絶対方角、可視範囲外の物体、最短経路。
- 食料・敵・味方・親子・所有者などの意味ラベルや、内部の物体ID。
- 他個体のエネルギー、年齢、繁殖意図、学習状態、ネットワーク、内部報酬。
- 寿命残り、世界の個体数、Nmaxの空き、観測者用の系統色、イベント名。

環境内部にはこれらの値が必要でも、個体入力とは別系統に置く。物体の色・形・動きは感覚情報として設計できるが、「食料だけ特定チャネル1」「親子だけ同色」等を入れれば事前構造になる。見た目の区別自体をなくす必要はなく、何を知覚しやすくしたかを記録し、必要なら外観変更による一般化を試す。

主候補は、既存の局所感覚の思想を保つ**小さな局所画像と音**である。画像は人間用の全体画面から切り出すのでなく、個体ごとの可視判定から生成する。遮蔽の背後は黒/不明として、非表示にした物体の輪郭やマスクが残らないようにする。身体向きに画像を回転し、絶対方角が画像配列から自動的に分からない仕様にする。

タイル種別配列、物体リスト、受信記号のone-hot、真の距離や相対座標を直接渡す案は計算上便利だが、**感覚インターフェースを変更する別条件**である。局所であればすべて同等とはみなさない。速度最優先の診断条件としては使えるが、画像・音条件への結果の外挿をしない。

自分の身体状態も決定が必要である。身体内受容として自分のエネルギー・損傷・疲労を少数の数値で感じる案は、他者の内部状態入力とは異なるが、従来の「視覚・聴覚のみ」からは追加になる。初期の推奨候補として比較する場合も、追加を明示する。視覚・聴覚のみを維持する条件では、身体の外見や音など許可した物理的な経路に限定する。数値バーを画像内に描いただけで追加情報が消えるわけではない。

### 3.2 操作を経験に結び付ける

身体の正面や手元への操作を用意し、対象の意味やグローバルIDによる指定は避ける。把持・放下・摂取・打撃・設置は局所の接触関係で成立し、不適切な操作は不成立または物理的な消耗として返る。成功/失敗のイベント名や「これは食べられない」という文字列を入力しない。

全部の操作を単一の巨大な離散選択にすると、移動しながら送信できない等の余計な制約が入る。移動、手の操作、送信、繁殖/睡眠状態を少数の独立した操作成分として用意し、同時にできない身体動作だけ排他にする案がよい。睡眠中の打撃不可等の制約は公開する。状態に応じたaction maskに隠れた対象種別・相手の同意・資源量が漏れないようにする。

障害物をすり抜ける、アイテムを直接インベントリへ転送する、自動採食、自動追尾、範囲内の相手との自動繁殖は、それぞれ技能や意思決定の一部を環境が代行する。採用するなら「便利な操作」として明記する。

## 4. 時間、更新順序、描画の分離

世界は整数tickで進む。同じtickの観測を全生存個体に生成し、全行動を受け取ってから世界を更新する。学習や睡眠計算に時間がかかれば世界全体の壁時計速度が下がり、遅い個体だけ年を取ったり、実行順の早い個体だけ食料を先取りしたりしない。個体の生涯時間は実験内tickで測る。

最初の更新順序案は次の通り。

1. `S_t`から全個体の局所観測と、前tickに伝播した音を生成する。
2. 各個体が自分の記憶・重みで判断する。独立した学習更新の回数/予算を適用する。
3. 移動・回転の意図をまとめ、同一タイルへの競合、入れ替わり、接触を規則で解く。
4. 接触・手元操作、摂取・打撃・設置・撤去をまとめて解決する。攻撃は同時にし、致死攻撃を受けた個体の攻撃だけID順で消さない。
5. 代謝・損傷・老化、死亡と遺留物を処理する。
6. 生存している親の繁殖進行・出生を処理し、その後に植物/獲物等を更新する。出生した子の初行動は次tickにする。
7. 送信音場を次tick用に作り、観測者用イベントと状態ハッシュを保存する。

順序は一つの提案であり、摂取直後の繁殖、攻撃と逃走、死亡時の出生などの境界事例を仕様化する。順序を変更したら環境バージョンを変える。同じタイルを争う場合は固定ID優先にせず、シード付き抽選や対称な不成立を使う。抽選規則でも生態への影響は残るため、衝突数と勝率を確認する。

世界状態更新、個体向けセンサー生成、推論/学習、人間向け描画、動画保存を分離する。headlessでは人間画面だけ止め、個体の画像生成は維持する。観測者は全体地図・系統・エネルギーを見てよいが、観測者用色や文字をセンサー生成に再利用しない。独立試行の並列化やバッチ化は可能でも、個体間の重み・経験・勾配・メモリを共有しない。

## 5. 通信路の設計と検証

### 5.1 最初の通信案

少数の異なる音を出す器官と、局所の混合音を聞くセンサーを用意する。沈黙と送信を区別し、送信の意味、文法、相手、返答は定義しない。音の送信と繁殖受容を別の操作にして、「この音が同意」という意味を環境に埋め込まない。

| 設計軸 | 最初の候補 | 比較で何が変わるか |
| --- | --- | --- |
| 形式 | 沈黙＋4音程度。波形または小さなスペクトログラムで受信 | 離散記号の直接入力・連続値・視覚信号は別の感覚条件 |
| 距離 | 視野より少し広い有限半径。外は受信不可 | 半径0 / 視野内 / 視野外で情報の有用性が変わる |
| 方向・距離手掛かり | 単耳の距離減衰音。音源の真座標は渡さない | ステレオは方向手掛かりを追加。距離減衰なしとは別条件 |
| 匿名性 | 発信者IDなし。個体ごとの固有声は最初はなし | 声質・方向・視覚的同定は、IDなしでも識別の足掛かりになる |
| 混信 | 全到達音を加算し、振幅上限でクリップ | 最近傍1者、最強1者、送信者別リストは違う社会構造を作る |
| 帯域 | 1 tickに1音、一定長。履歴は個体自身が記憶 | 沈黙を含むK種類なら理想的な単独送信の上限は概ねlog2(K)/tick。混信・雑音で実効容量は低下 |
| 遅延 | 1 tick。現在の送信を同tickの判断へ戻さない | 遅延の増加で対話・追従の成立が変わる |
| 費用 | 小さな送信エネルギー/時間費。初回は無費用も比較 | 無費用の常時発声と、高費用で無言になる状態を切り分ける |
| 自分の声 | 聞こえる場合と遮断する場合を明記 | 自己刺激、内部記憶の外部化、他者との通信が混ざる |

4音は4語ではない。音波の混合を入力する場合も、周波数ごとの感度や振幅分解能は人間が決めたセンサーである。受信者ごとに送信者一覧を作ると、匿名の共有音場から分離済み通信回線への変更になる。

通信のコストは世界の物理的な消費として設け、発声量、相互情報量、相手を動かした量への外的な加点を作らない。通信しなくても採集や自己複製で生きられる基準条件を残し、「通信がないと全員確実に死ぬ」条件だけを成功例にしない。

### 5.2 相関から意味を結論しない

Loweらは、発話と発話者の行動が相関しても、受信者が発話を使っていない実例を示した。したがって発声頻度・信号エントロピー・食料との相関だけでは通信の成立を判断できない。[一次論文: On the Pitfalls of Measuring Emergent Communication](https://arxiv.org/html/1903.05168)

保存点から実験を分岐し、他の観測と身体状態を保ったまま受信音だけを、沈黙、頻度を保ったシャッフル、他個体の同状況の音、遅延した音へ置き換える。まず学習を止めた短い分岐で受信者の行動分布・接近/回避・採食・繁殖試行への効果を測り、別に学習を続ける長い分岐で適応を測る。音を止めた条件で送信費まで消すと、情報の喪失と費用削減が混ざる。

「音が行動を変えた」「他者の状態について情報を伝えた」「生存や出生に役立った」「構成的な意味体系がある」は別の主張である。単純な呼び寄せ・威嚇・同期信号も通信になり得るが、それだけで人間的な言語とは呼ばない。未知の相手との組み合わせ、子への継承範囲、学習停止個体、外観や地形の変更でも調べる。

## 6. 食料、資源循環、狩り、地形偏り

### 6.1 最小の生態と収支

植物等への外部エネルギー流入、食料への変換、個体の摂取、代謝による散逸、子への移転、遺体/食べ残しを別に記録する。**エネルギーが代謝で失われる完全閉鎖世界では、長期に持続する供給源がない。** 栄養や材料の再利用と、エネルギーの再生を混同しない。光合成に相当する流入を置くなら、それを明示的な世界ルールにする。

最初は上限のある局所食料パッチと遅延再生でよい。食料が個体の真下へ即座に無制限再生すると、静止と自動摂取だけで生存できる。不活動の無期限生存を避けるには基礎代謝を常に正にし、睡眠でもゼロにしない。ただし、何もせず安全に休むことが局所的に合理的な時間は残してよい。

遺体に固定量の食料を必ず与えると、低コスト出生→殺害→食料化で資源が増える可能性がある。親から子への移転、身体材料、遺体の可食量を同じ台帳で扱い、回収率を1以下にする。死亡による食料が必ず繁殖費を上回らないかを確認する。攻撃で失った「体力」と体内に残る可食資源を分ける場合も、その二重計上を防ぐ。

Polyworldは視覚、原始動作、代謝、死亡時の食料化、双方の繁殖動作による出生を統合した先行例である。ただし原論文には、定着前に採食・繁殖・移動等を採点して個体を補充するGAモードもある。これを今回の「外的課題報酬なし・自動補充なし」の成立根拠として丸ごと移植しない。[一次論文: PolyWorld: Life in a New Context](https://shinyverse.org/larryy/Yaeger.ALife3.pdf)

### 6.2 枯渇と地形偏り

最初は採り尽くしても遅く再生する条件で、単純な探索・運搬を観測する。その後に、近傍の残存植物が多いほど再生しやすい条件、完全枯渇が回復不能な条件、季節や局所変動を追加する。初回から不可逆枯渇にすると、探索中の偶然だけで世界が壊れ、学習前の全滅が支配的になりやすい。

Harvestの近傍依存再生、Cleanupの公共資源維持は、資源規則が社会的ジレンマを作る具体例である。一方、同研究は採食報酬と設計済みの不平等回避を使っている。今回は生態的な因果関係の比較例として参照し、他者の報酬入力や社会的選好を無断で採用しない。[一次論文: Inequity aversion improves cooperation in intertemporal social dilemmas](https://proceedings.neurips.cc/paper/2018/file/7fea637fd6d02b8f0adf6f7dc36aed93-Paper.pdf)

資源の総量を同じにして、均一、集中パッチ、緩い勾配、障害物で分かれた複数地域を比べる。地形変更と同時に食料総供給を変えない。資源偏りは移動・接触・縄張り・孤立を誘導するが、小集団では単に会わないこともあるため、接触率、同時可視率、通信到達率、地域間移動を測る。

有限で複数の資源が分化を生む研究例はあるが、Avidaの論理演算への資源/計算速度割当は今回の身体的な採食と異なる。複数資源を置けば小集団で必ず分化するという根拠にはならない。[一次論文: Adaptive Radiation from Resource Competition in Digital Organisms](https://cse.msu.edu/~ofria/pubs/2004ChowEtAl.pdf)

### 6.3 狩り

最初の統合後に、局所視覚で逃げ、植物を消費して有限資源で再生産する単純な獲物を加える。獲物の方策は固定の小さなスクリプトでよく、獲物用に独立した学習器を追加する必要はない。獲物数上限と学習個体数上限は分ける。

打撃は接触・方向・クールダウン・消耗・負傷という身体ルールで定義する。獲物を倒すと遺体を摂取できるが、狩り成功への点数は与えない。最初から「二者が近くにいると肉が倍になる」「二人でないと絶対に倒せない」という人数ボーナスを入れない。逃げる進路を塞ぐ、攻撃と防御を分担するなどが物理から有利になる余地を作る。

協同狩りの参考としてWolfpackは有用だが、原研究は捕獲地点近傍の相手へのチーム報酬を定義している。狩りの協調が出ることと、協調に有利な報酬表を設計したことを分ける。[一次論文: Multi-agent Reinforcement Learning in Sequential Social Dilemmas](https://arxiv.org/html/1702.03037)

獲物が硬いだけでは、自明な集団攻撃になる。単独で成功可能な小獲物と、より危険な大獲物を置く比較や、同じ総食料で採集のみ/狩り併用を比べる。生態制御に必要な獲物の再供給と、無限に湧く無料の肉を区別する。

## 7. 建築の機能と睡眠

### 7.1 建築

最小の建築は、取得できる1種類の材料を運び、手前の空きタイルへ置き、撤去できる仕組みでよい。設置物は通行・視線を遮り、有限の耐久を持ち、攻撃や経年で壊れ、材料の一部が回収される。この物理的な効果がないと、ブロック設置量は機能的な建築の証拠にならない。

最初は壁・遮蔽物だけとし、扉、床、貯蔵庫、橋、栽培、屋根は後で追加する。橋には通れない地形、屋根には天候、貯蔵庫には腐敗や持ち運び制約が必要である。機能のためだけに多数の生理・災害を同時実装しない。壁は逃避、待ち伏せ、視線切り、資源封鎖にも使え、必ず協調的になるよう設計しない。

所有者だけ壊せる、親子だけ通れる、同じ集団の建物で眠ると加点される等の制度は最初は入れない。所有権や集団所属を環境が与えることになる。設置者はログに残してよいが、個体入力や利用許可に使わない。

道具使用・環境改変の先行例としてhide-and-seekの研究があるが、明示的な勝敗報酬、チーム、操作規則の上で成立している。今回の無課題報酬・独立個体への直接的な成立保証ではない。[一次論文: Emergent Tool Use From Multi-Agent Autocurricula](https://arxiv.org/html/1909.07528)

評価では設置数と別に、保存分岐で対象構造物を撤去/同じ材料の別配置へ置換し、通過可能性、被害、睡眠中断、資源アクセス、他者の行動が変わるか調べる。建築者死亡後にも残れば環境継承を観測できるが、「遺伝による継承」と同一視しない。

### 7.2 睡眠

世界内の睡眠状態と、内部の記憶再処理を別のスイッチにする。睡眠中は移動/手の操作を止める、感覚更新を減らす、起床に遅延を置く等の世界内負担を定義する。睡眠中も年齢・基礎代謝・危険は進む。安全な寝場所を人間が指定しない。

最初は睡眠を選べる状態だけ用意し、内部処理の機構が確定後に接続する。「睡眠すると疲労が必ず回復する」生理的利益を入れた条件と、同じ生理で内部学習だけ変えた条件を分ける。眠った量への加点や、睡眠中の計算だけ無制限にすることはしない。

睡眠に多くの実GPU時間を使っても、本人だけ実験内時間を止めない。内部処理の追加計算はwall-clock、更新回数、使用メモリで記録し、世界内の睡眠時間と併記する。睡眠の効果比較は「同じ世界tick」と「同じ計算量」の両方で行う。

## 8. 寿命・成熟・死亡・出生・系統

### 8.1 生涯

成熟前は繁殖不能にし、出生直後の無限増殖を防ぐ。幼体を操作不能にする必要はなく、最初は成体と同じ操作で、成熟期間のみ課す案が単純である。親の自動給餌や自動追従は育児技能を環境が代行するため保留する。

初回は固定または狭い分布の年齢上限と、エネルギー枯渇・致命損傷による死亡を用意する。成熟・寿命を最初から進化可能にすると、不死や即成熟を選ぶ方向が他の結果を圧倒し得る。固定寿命が生態をどう変えるかは後で、上限延長・加齢ハザード・加齢なしの比較を行う。

死亡は終了イベントであり、同じ重み・記憶・IDで自動再出現させない。コピーの出生は新しいIDと出生時刻を持ち、死亡した親の復活とは区別する。個体が最後に受ける観測、遺体の残留、進行中の出生の中止を仕様化する。

### 8.2 二親繁殖・自己複製・繁殖しない選択

繁殖しない状態を標準とし、後から変更できる。二親繁殖は双方が同時に受容状態で、隣接・成熟・資源・時間の条件を満たす場合だけ進む。相手の内部受容フラグを観測させない。相手選択を内部ID一覧で行わず、身体の向きと接触で行う。複数の候補が同時にいる場合の組合せもシード付き対称規則で決め、同一tickに同じ親が多数の子を作らないようにする。

自己複製にも同等の子の初期資源、場所、成熟期間と独立した学習状態を要求する。繁殖には時間/資源を使い、完了まで親が生存・接触を維持するか、開始時だけ接触が必要かを定める。接触維持は二親方式へ追加の協調課題を課すため、最初は短い接触で開始し、開始後は各親が負担する方式が比較しやすい。

費用の基準案は、子の初期資源`E_child`と散逸する追加負担`B`を分け、自己複製は一親が`E_child+B_clone`を、二親は合計`E_child+B_two`を折半する。基準条件では`B_clone=B_two`とする。同じ総費でも二親には探索・同意費があり、反対に資源を共同負担できる利益がある。**中立な唯一の費用設定は存在しない。** 散逸する追加負担の比`B_two/B_clone`の0.5 / 1 / 2程度、所要時間、接触条件、子の初期資源を感度比較し、一方を必ず勝たせるよう都度調整しない。これは総費の比ではなく、両方式とも`B>=0`かつ総費`>=E_child`を必須とする。

例として`E_child=30, B=10`なら複製は40、二親は各20を負担する。これは動作確認用の仮値で、二親方式の生物学的な正解ではない。子へ渡る30を親から引き、追加10を散逸として記帳する。子の資源や可食材料を無から作らない。

出生開始時に親の資源をエスクローへ移し、容量枠を原子的に予約する案が単純である。完了時に`E_child`を子へ渡し、進行に応じた`B`だけ散逸させる。中止時には未使用資源だけを返し、親が死亡した場合も遺体とエスクローで二重に計上しない。出生先は親の近傍の空き位置とし、空きがない場合の中止/短い待機、その間の代謝と返金を定義する。遠隔の空き地点への自動転送はしない。これらの処理は二親と複製で共通化し、容量枠の長期独占を監視する。

学習済みネットワークの二親混合が壊れるなら、環境コストだけを等しくしても公平な繁殖方式比較にならない。環境の出生イベントと、継承ハンドラを分離し、重み・学習則・内的評価・記憶・変異の範囲を別仕様で確定する。ランダム新生個体で出生処理を検証することはできるが、その結果を遺伝や二親繁殖の有効性の検証とはしない。親子の活動中の重み/経験同期は行わない。

有性生殖の適応上の利点についても、小集団で自動的に現れると期待しない。実生物の実験でも利点が個体数に依存した例があり、小集団・小さな遺伝表現へそのまま外挿できない。[一次研究: Sex releases the speed limit on evolution](https://pubmed.ncbi.nlm.nih.gov/12478292/)

### 8.3 初期個体数とNmaxを分ける

初期個体数は初期値であり最大値ではない。NmaxはVRAM/RAM、出生時の一時複製、最悪時の学習状態と睡眠メモリを含めて計測後に決める。親・子・進行中の出生で予約された容量を含む数え方を定義する。

最初の推奨は、上限到達時は新規出生の開始を**資源を引く前に不成立**とする方式である。同じtickの出生候補が空き枠を上回る場合は、シード付き抽選で成立させる。学習が速い順、系統ID順、先にGPUへ送られた順、観測者の「優秀さ」で選ばない。上限のために既存個体を殺さない。

上限時の不成立も選択圧であり、中立ではない。枠が空くまでの待機列は先着・長期待機を優遇し、卵だけ大量に置く方式は容量予約を独占し得る。別条件で比較するならルールを明示する。親に世界全体の空き枠数を教えず、通常の身体的な不成立として経験させる。

Nmax付近に長く張り付き出生が大量拒否される場合、結果は生態だけでなく計算容量に制限されている。上限滞在率、拒否出生数、方式/系統別拒否率を必ず報告し、Nmaxや資源量を変える。Nmaxを変える際は初期密度・資源流量・マップ面積のどれを固定したかも示す。

### 8.4 全滅と新生個体

全滅は結果として保存し、その試行を終了する。世界を同じまま新規個体を再投入する場合は、別の介入試行IDにし、自然な系統継続として数えない。乱数初期値からのやり直し、保存点からの分岐、管理者による補充を区別する。

個体数が減っても自動で初期個体数へ戻さない。診断用に強制補充を使う場合は、出生ログに`administrator_created`と記録し、自然出生・コピー出生と分離する。小集団では初期偶然・交配相手の不在・系統ドリフトが大きいので、単発の全滅や成功では一般性を主張しない。

系統ログには、個体ID、出生/死亡tickと原因、繁殖方式、親ID（自己複製は一親）、継承仕様バージョン、親/子の出生直前/直後のチェックポイント参照、変異シード、出生位置、移転資源、管理者生成か、容量拒否を記録する。二親は木でなくDAGとして追い、子孫数の両親への二重計上方法を定義する。記録用IDをセンサーへ漏らさない。

## 9. Nature論文の適用範囲

[Grouchy et al., On The Evolutionary Origin of Symbolic Communication (2016)](https://www.nature.com/articles/srep34615) の本文は[NatureのPDF](https://www.nature.com/articles/srep34615.pdf)で確認した。

NoiseWorldでは、絶対x/yを知る個体が最近傍1者の匿名な一次元信号を受け、距離・方向は受信媒体から分からない。接近すると自動二親出生し、出生ごとにランダムな個体を死亡させる。制御式は遺伝・変異で進化し、今回の独立した生涯学習、任意の不繁殖、自己複製、有限資源生態とは異なる。同研究は目的適応度を置かないが、相手探索・出生・ランダム死亡が明確な選択圧を作っている。

参考にするのは、意味を決めない通信路、連続的な親子共存、通信を止めた比較、信号と行動の機構分析である。絶対座標入力、自動繁殖、最近傍専用回線、出生時のランダム淘汰はそのまま採用しない。特に自己複製を許すと相手探索の必要が減るので、同論文の通信成立を今回の予測にはできない。同論文における「symbolic」の判定基準も、人間の言語全般の獲得と同義にはしない。

## 10. 連続世界と試行の区切り

| 運用 | 利点 | 制約・解釈 |
| --- | --- | --- |
| 連続世界、保存のみ | 建築・資源枯渇・系統・長い相互作用が残る | 初期履歴への依存、全滅、長期計算が大きい |
| 一定tickで終了、世界を初期化する独立試行 | 同じ予算で条件とシードを比較しやすい | 長期的な蓄積や環境継承を途中で切る |
| 生涯だけ区切り、世界を維持 | 親子共存と環境履歴を保てる | 世代単位の一斉更新と混同しない |
| 管理者の世代選抜・補充 | 学習/継承機構の診断には使える | 今回の世界内での任意出生を検証する主条件ではない |

推奨は「連続世界の独立試行を、有限の観測期間で実行」である。試行終了はデータ収集の打切りであり、世界内の死亡ではない。生存時間解析では右打切りとして扱い、最後まで生きた個体を寿命到達と数えない。保存・プロセス再起動は世界のリセットでも、世代交代でもない。

Neural MMOは永続世界・可変個体数・局所的な資源競争の工学的な参考になる。ただし長く存在するだけでは長期計画が必要とは限らず、同じ短い採食問題の反復でもよい。また原研究のRL報酬や入力表現は今回と異なる。[一次論文: Neural MMO](https://arxiv.org/abs/1903.00784)、[著者による環境実装](https://github.com/openai/neural-mmo)

建築持続の効果は、同じ個体/学習状態の保存点から、世界改変を維持する条件と、資源・建築だけ初期化する介入条件を分岐して比較する。子だけを新しい地形へ置く条件では、環境継承と出生時のモデル継承を切り分ける。主世界へ評価用の複製を戻さない。

## 11. 段階的追加と比較条件

1. **環境機構の確認**: 小地形、局所画像/音、接触操作、食料・代謝・寿命、出生/死亡、Nmax、記録と再開。定数/ランダム/検証用方策で収支と更新公平性を確認。描画なしとありでセンサー・世界軌跡が同じか確認する。
2. **学習の統合**: 1種類の採集資源、固定寿命と成熟、両繁殖方式、通信利用可能、睡眠状態。学習停止・通信受信停止・睡眠内部処理停止の比較を行う。初期生存猶予と学習更新回数が適切か測る。
3. **生態と地形**: 資源の均一/偏在、回復可能/不可逆枯渇、運搬・貯蔵、地形の連結性。総供給を合わせ、接触機会の不足を確認する。
4. **狩り**: 固定方策の有限獲物、危険と摂取可能資源。採集のみと同等総食料の条件、単独狩り可能性、混雑効果を比較する。
5. **機能的な建築**: 材料1種類と壁、遮蔽・通行・耐久。建築機能停止/撤去介入、改変の世代間持続を比較する。
6. **頑健性**: Nmax、密度、資源流量、寿命、二親/複製の費用と時間、通信帯域・距離・雑音、未知地形、未知相手。まず一要因、交互作用が疑われた部分だけ小さな要因計画を使う。

最初から全部の要素を載せて一本だけ長く走らせない。環境・学習則・継承則を同時に変更した場合は、変更の寄与を個別に特定できないと報告する。短い試行で成立した現象は、条件を固定した長期試行で維持を調べる。

## 12. 重要な失敗モード

| 失敗モード | 確認する量/比較 | 解釈・対処 |
| --- | --- | --- |
| 不活動・常時睡眠で無期限生存 | 無採食の生存、基礎代謝、真下への再生 | 代謝0や自動採食を確認。休息そのものを罰する報酬は入れない |
| 全員が学習前に死亡 | 初回採食までの時間、更新回数、到達可能性 | 初期猶予・操作・探索・学習器を別に診断し、知能の不可能性としない |
| 一方の繁殖方式の自明な支配 | 費用、探索時間、成立率、子の能力 | 費用表や継承破壊が原因か比較。一方の出現を成功条件にしない |
| Nmaxによる恣意的な淘汰 | 上限滞在率、拒否率、順序依存 | 既存個体のランダム殺害を避け、容量感度を示す |
| ID順/実GPU速度による先取り | ID別競合勝率、並列順の変更 | 同時意図とシード付き公平規則を使う |
| 通信の見かけの相関 | 受信だけの介入、短期行動分布 | 発話者の状態相関だけで通信や言語と判定しない |
| 無限発声・自己刺激 | 自分の声遮断、費用保持で受信遮断 | 外部記憶・探索刺激と対他者通信を区別 |
| 協調を最初から埋め込む | チーム/人数ボーナス/所有権/自動給餌の有無 | 物理的相互作用と制度・報酬を区別し基準条件を残す |
| 子を生んで食べると資源が増える | 親→子→遺体の台帳、回収率 | 出生の無償資源や死亡時の最低食料を検査 |
| 建築が飾り・世界を永久封鎖 | 撤去介入、連結性、材料回収、耐久 | 機能と不可逆な閉塞を測る。無限材料を供給しない |
| 世代変化と生涯学習の混同 | 学習停止、継承範囲変更、新生個体 | 継承・出生後の学習・環境履歴を分離する |
| 小集団の偶然を一般化 | 独立シード、初期配置、密度条件 | 平均だけでなく全滅・少数成功を含む分布を報告 |
| 監視データが入力や報酬へ混入 | 観測契約監査、評価モジュールの遮断 | 真座標・系統・成績は観測者専用にする |

## 13. 報酬と切り離して測る量

評価器は世界と個体を読み取るだけの別プロセス/モジュールにし、結果を個体の観測・報酬・勾配へ返さない。主実験では生存時間、採食、通信、出生、協調、建築への加点を作らない。API上のreward欄が必要なら未使用/0として、それが生存点数でないことを明記する。死亡による活動終了と、TD学習の死亡ペナルティも別である。

| 分野 | 観測指標 | 必要な比較・注意 |
| --- | --- | --- |
| 生存・集団 | 年齢別死亡原因、生存曲線、個体数、全滅率、出生/死亡流量 | 有限試行の右打切り、管理者補充を分離 |
| 生涯学習 | 年齢に伴う操作成功、環境変更後の回復、記憶保持 | 学習停止、新規環境、同じ計算量の比較 |
| 資源生態 | 流入/散逸/蓄積/移転、採集/狩り量、枯渇と回復、地域占有 | 総資源と個体密度、視野と接触機会を併記 |
| 繁殖 | 方式別試行・開始・中断・成立、親負担、子の成熟・生存、系統DAG | 上限拒否と同意不成立を分け、継承仕様を固定 |
| 通信 | 発声・受信量、混信、帯域使用、信号と状況の関係、受信介入効果 | 自己音、費用、共通観測を統制。相関と因果を分離 |
| 社会相互作用 | 接触網、資源移転、妨害、共同作業、相手依存の行動変化 | 密集しただけか、相手の存在/行動に因果的に依存するか |
| 建築 | 設置/撤去、耐久、配置の持続、通路/視界/被害への効果 | 撤去・置換介入。構造量だけで機能としない |
| 睡眠 | 睡眠率、場所、死亡/中断、内部更新数、保持/干渉 | 生理効果と内部処理、tickと計算量を分離 |
| 計算 | world tick/s、agent decision/s、更新/s、出生時ピーク、RAM/VRAM | 初期個体数だけでなくNmax、睡眠同時実行でも計測 |

協調は「近くにいる」「同時に同じ操作をした」だけで認定しない。相手の行動を置換/除去した分岐で、複数個体の資源・被害・生存機会がどう変わるか確認する。助ける/裏切るというボタンや、事前の集団ラベルは必要ない。

観測指標を使った実験者の条件選択にも選択バイアスが入る。探索段階で調整した条件と、条件を固定した確認試行を分け、全滅・停滞・負の結果も残す。大量の指標から目立つ相関だけ選ばず、中心となる比較と判定を実行前に記録する。

**同じ世界内のN体は、N個の独立試行ではない。** 食料・相手・地形・系統を共有して結果が依存するため、条件比較と不確実性の基本単位は独立に初期化した世界/シードとする。個体ごとの観測は世界内の分布として残し、集計や再標本化でも世界単位のまとまりを保つ。保存点からの介入分岐は対応のある比較として扱い、独立世界数が増えたとは数えない。

## 14. 速度計測と再現性

手元の3995WX 64コア、約110GiB RAM、32GB級GPU×3という構成だけで実行速度やNmaxを予測しない。GPUの学習性能・互換性は未検証であり、環境を高速化しても学習/睡眠/出生が律速になり得る。

計測は次の分解で行う。

- 世界更新のみ、次に個体向け画像/音生成を加えた速度。
- 推論のみ、通常学習あり、睡眠あり、出生ありの、初期個体数ごとの速度。
- Nmax付近でのピークRAM/VRAM、出生時に親子モデルが同時存在する負荷。
- 人間描画なし/あり、動画なし/あり、保存間隔による差。
- world tick/sと、可変個体数を反映する`sum(N_alive)/wall-clock`のagent decision/sを併記。
- 推論、学習、睡眠、観測生成、保存、モデル複製の時間と、経験保持量。

モデル規模は固定せず、候補ごとに必要なメモリを見積もる。重み、勾配、optimizer状態、活性、リプレイ/記憶、出生の一時バッファ、睡眠で増える状態、ログを含める。CPU64コアの全使用やGPU3枚への分割も計測後に決める。個体学習をまとめて計算しても独立性を維持する。

世界、個体初期化、行動サンプリング、学習、資源再生、獲物、競合解決、出生変異の乱数ストリームを分離する。個体が1体増えただけで世界の全資源乱数がずれないよう、イベント/個体別のキーを使う。コードcommit、設定、観測/行動/継承バージョン、依存、ハードウェア、初期状態、全RNG状態を記録する。

チェックポイントには世界、建築/資源、tick、全個体のID/年齢/身体、重み、optimizer、記憶、経験、内的評価、睡眠/出生進行、RNGを含める。再開前後で同じ行動列を与えた環境状態ハッシュが一致することを確認する。GPUの非決定的計算がある場合は、世界遷移の完全再現と、学習を含めた統計的再現を区別する。

保存からの介入比較は同じ世界とモデル状態から始めるが、分岐後の行動変化で状態が発散する。短期の受信効果と、長期の生態的効果を別に測り、共通乱数を使ったことだけで厳密な同一条件を主張しない。

## 15. 実装前に残る決定

- 局所画像・音の具体形、身体内受容を加えるか、純粋な視覚/聴覚条件をどう保つか。
- 独立学習・内的評価・継承の仕様。環境だけで学習の駆動源は決まらない。
- 実測した計算容量によるNmax、出生容量予約、睡眠/出生ピークの余裕。
- 学習更新数と操作探索に対して、成熟・寿命・初期生存猶予が十分か。
- 二親と複製の総費、接触/同意、所要時間、継承範囲と子の初期能力。
- 音場の混信・方向/距離手掛かり・自己音・費用の基準条件。
- 植物の外部エネルギー流入、遺体の栄養回収、不可逆枯渇の導入段階。
- 狩りと建築を追加する時点、および資源・危険・通行への最初の実効果。
